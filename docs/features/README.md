# 功能说明文档

`docs/features/` 记录 Story Studio 当前已经落地的功能现状，帮助 AI 和维护者快速理解现有行为。

## 与其他文档的区别

- `docs/features/*.md`：描述当前功能事实、入口、数据流、关键文件和验证入口。
- `docs/specs/*.md`：描述一次新增功能或行为调整的规格、验收标准和完成记录。
- `docs/plans/YYYY-MM/*.md`：记录从规格拆出的执行计划和历史推进状态。
- `docs/adr/*.md`：记录长期架构决策。
- `docs/architecture.md`：记录系统总览和模块边界。

## 维护规则

功能更新后，如果主流程、页面入口、数据结构、状态流、接口关系或关键边界发生变化，应同步更新对应功能说明。没有对应文档时，先新增最小功能说明，再在变更 Spec 中链接它。

## 建议结构

每个功能说明优先包含：

- 功能目的
- 用户入口
- 主流程
- 关键文件
- 数据结构
- 状态流和副作用
- 边界情况
- 验证入口
- 最近相关 Spec / Plan
