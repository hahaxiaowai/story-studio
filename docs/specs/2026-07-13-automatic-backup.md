# Tauri 自动备份

## 状态

- 当前状态：已确认
- 日期：2026-07-13

## 背景

Story Studio 已支持用户手动导出完整 JSON 备份，并在预览摘要后确认恢复。现有流程需要用户主动操作，无法在持续创作期间自动保留恢复点；如果用户忘记导出，主数据文件损坏或误操作后缺少可恢复版本。首期自动备份聚焦 Tauri 桌面端，在应用运行期间定时检查数据变化，并把可轮换的完整文档备份写入应用数据目录。

## 已确认事实

- 当前统一文档通过 `useStudioData()` 加载和保存；Tauri 主数据由 `load_studio_data` 与 `save_studio_data` 命令读写应用数据目录。
- 当前手动备份保存原始 `StudioDataDocument` JSON，并通过 `parseStudioDataBackup()` 校验、迁移和恢复。
- 当前仅支持手动完整备份，不存在自动备份调度、轮换文件或自动备份恢复列表。
- 用户已确认首期仅支持 Tauri、固定 10 分钟检查、分层保留、现有对话框入口、默认开启可关闭，以及恢复前保护备份。

## 目标

- Tauri 桌面端默认开启自动备份，每 10 分钟检查一次当前文档。
- 应用数据加载完成后立即执行首次检查。
- 仅在当前文档尚无相同 `updatedAt` 的有效备份时创建新文件，避免重复写入。
- 使用小时与日期时间桶分层保留最近 7 天的恢复点。
- 用户可以在现有“数据备份”对话框查看状态、关闭或开启自动备份，并预览和恢复自动备份。
- 恢复自动备份前先保存当前文档的保护备份；保护失败时不得覆盖当前数据。
- 自动备份异常不得阻断主数据保存、手动导出或文件导入恢复。

## 范围

- 仅支持 Tauri 桌面运行时；Web 端继续使用现有手动导出和文件恢复。
- 前端负责 10 分钟调度、运行状态、开关和用户交互。
- Rust 原生层负责设备设置、备份目录、原子文件写入、列表读取、安全 ID 校验和分层轮换。
- 自动备份保存完整原始 `StudioDataDocument` JSON，继续复用现有迁移、校验、摘要和恢复逻辑。
- 备份来源区分为定时备份 `scheduled` 和恢复前保护备份 `pre-restore`。
- 现有备份对话框新增 Tauri-only 自动备份管理区。
- 增加中英文文案、Rust 单元测试、TypeScript 模块测试、UI 接线测试和真实 Tauri 验证。

## 非目标

- 本次不为 Web 端保存 IndexedDB 自动快照。
- 本次不实现应用退出后的系统后台任务、操作系统计划任务或云同步。
- 本次不新增单条备份手动删除、永久保留、重命名、备注或导出自动备份的操作。
- 本次不实现增量备份、压缩、加密或工作区级局部备份。
- 本次不修改手动 JSON 备份的文件结构和兼容范围。
- 本次不把自动备份开关写入故事文档，也不随故事备份导入导出。

## 用户流程

### 自动创建

1. Tauri 应用完成统一文档加载。
2. 自动备份控制器读取本机开关；首次没有设置时按开启处理。
3. 控制器立即检查一次，之后每 10 分钟检查一次。
4. 开关关闭时跳过检查和写入，但不删除已有备份。
5. 控制器读取有效备份索引；只要其中存在与当前文档相同的 `updatedAt`，本轮只刷新检查状态。
6. 没有相同版本时，原生层以 `scheduled` 来源原子写入完整 JSON。
7. 新文件成功后执行分层轮换；写入失败时不删除旧备份。

### 查看和开关

1. 用户打开现有“数据备份”对话框。
2. Tauri 运行时展示自动备份开关、最近检查时间、最近成功备份时间、下次检查时间和备份数量。
3. 用户可以刷新列表；列表按创建时间从新到旧展示来源、创建时间、文档更新时间、文件大小和数据摘要。
4. 用户关闭自动备份后停止后续定时检查，已有文件保持不变。
5. Web 运行时不展示自动备份管理区。

### 恢复自动备份

1. 用户选择一份有效自动备份。
2. 前端读取并使用现有 `parseStudioDataBackup()` 校验和迁移文档，只展示待恢复摘要，不修改当前数据。
3. 用户确认覆盖恢复。
4. 原生层先把当前文档写成 `pre-restore` 保护备份。
5. 保护备份失败时中止恢复，当前内存和持久化数据保持不变。
6. 保护备份成功后调用现有 `replaceDocument()` 原子替换并持久化目标文档。
7. 主数据保存失败时沿用现有内存回滚；保护备份继续保留。
8. 恢复成功后刷新自动备份列表和状态。

## 核心流程与关键异常场景

- 成功路径：数据加载后定时检查版本，变化时原子写入并轮换；用户可在现有对话框预览和保护性恢复。
- 失败路径：写入或设置读取失败只更新自动备份错误；保护备份失败时禁止恢复；主数据恢复失败时回滚内存文档。
- 取消或中断：用户关闭开关后停止检查；关闭应用时清理定时器，不额外承诺退出备份。
- 数据缺失或兼容行为：目录缺失时创建；损坏文件保留并禁用恢复；有效旧 schema 仍由现有解析器迁移；Web 行为保持不变。

## 决策记录及被放弃方案

- 采用方案：前端调度加 Tauri 原生备份服务，原生文件保持原始统一文档 JSON。
- 放弃 Rust 后台定时器：设备设置、页面状态和错误反馈需要额外事件同步，生命周期复杂度更高。
- 放弃扩展 `StudioStorageDriver`：会把主数据保存与版本文件管理耦合，也不符合固定时间检查语义。
- 放弃 Web 同期支持：浏览器只能提供同介质 IndexedDB 快照，行为和可靠性与桌面文件备份不同。
- 放弃单纯按数量或 7 天全量保留：分层时间桶能以可控容量提供更均衡的恢复点。

## 假设与待业务确认

- 假设：应用运行期间的 10 分钟检查能覆盖首期主要数据保护场景；系统级后台备份推迟到后续规格。
- 假设：以 `StudioDataDocument.updatedAt` 判断已有版本足以避免重复备份；本期不引入内容哈希。
- 待业务确认：无。会改变核心方案的产品问题均已关闭，其余扩展已列入非目标。

## 架构与模块边界

### 前端调度

- 新增 `apps/studio/src/modules/storage/useAutomaticBackup.ts`，负责控制器生命周期、立即检查、10 分钟定时器、并发互斥、开关和状态刷新。
- 控制器在应用级入口挂载，不能依赖备份对话框是否打开。
- 同一时刻最多运行一个检查任务；上一轮尚未结束时跳过本轮。
- 失败只更新可见错误状态，下一轮继续重试。
- Web 运行时不创建控制器副作用。

### 前端领域和适配

- 新增 `apps/studio/src/modules/storage/automaticBackup.ts`，集中定义备份来源、列表项、设置、运行状态和错误映射等领域类型及纯逻辑。
- 新增 `apps/studio/src/modules/storage/tauriAutomaticBackup.ts`，封装 Tauri command 参数与返回值。
- 自动备份不扩展 `StudioStorageDriver`；主文档读写与版本文件管理保持独立职责。
- 前端只传递原生层生成的不透明备份 ID，不接收或拼接任意文件路径。

### Rust 原生服务

- 在 `apps/studio/src-tauri/src/lib.rs` 增加读取和保存自动备份设置、创建备份、列出备份、读取指定备份等命令。
- 自动备份目录固定为 `app_data_dir/automatic-backups/`。
- 写入沿用临时文件加 rename 的原子策略；成功写入后才运行轮换。
- 原生层校验备份 ID，只允许访问索引中受管理的文件，拒绝路径分隔符、父目录和任意绝对路径。
- 设置属于设备运行数据，单独保存在应用数据目录；首期只包含 `enabled`，缺失时默认为 `true`。

## 数据模型

前端和 Tauri command 使用等价的传输结构：

```ts
type AutomaticBackupSource = 'scheduled' | 'pre-restore'

interface AutomaticBackupEntry {
  id: string
  source: AutomaticBackupSource
  createdAt: string
  documentUpdatedAt: string
  byteSize: number
  status: 'valid' | 'corrupted'
  summary?: StudioDataBackupSummary
}

interface AutomaticBackupSettings {
  enabled: boolean
}
```

- 有效文件保存原始 `StudioDataDocument`，不增加备份 envelope。
- 文件名编码来源和创建时间，但文件路径不暴露给前端。
- 列表摘要由原生层安全读取后返回，前端读取目标备份时仍必须经过现有 TypeScript 解析和 schema 迁移。
- 损坏文件返回最小索引信息和 `corrupted` 状态，不提供文档内容或恢复操作。
- 本次不修改 `StudioDataDocument`，schema 保持 14。

## 调度和轮换规则

### 检查规则

- 数据加载完成后立即检查，随后每 10 分钟检查。
- 关闭开关时停止定时检查；重新开启后立即检查并重建定时器。
- 检查时只要任一有效受管备份的 `documentUpdatedAt` 等于当前文档 `updatedAt`，就不创建重复文件。
- 没有备份或当前版本尚未备份时创建 `scheduled` 文件。
- 最近检查时间属于当前进程状态；最近成功备份时间从有效索引计算。

### 分层保留

- 时间桶使用本机时区，与 UI 展示日期保持一致。
- 最近 24 小时按自然小时分桶，每个小时保留该桶中创建时间最新的一份。
- 创建时间处于第 2～7 天的备份按自然日分桶，每天保留最新的一份。
- 超过 7 天的备份删除。
- `scheduled` 与 `pre-restore` 共同参与相同时间桶，不为来源单独保留额度。
- 全局创建时间最新的一份始终保留，以应对系统时间回拨或异常时间戳。
- 损坏文件不自动删除，也不参与有效备份时间桶；界面提示用户文件损坏。
- 单个旧文件删除失败不阻断其他删除，也不撤销本次已成功写入的备份；失败会进入可见错误状态并在后续检查重试。

## UI 结构

- 继续使用 `apps/studio/src/components/DataBackupDialog.vue`，不新增导航页面。
- 自动备份区仅在 `isTauriRuntime()` 为真时展示。
- 顶部展示开关与运行状态；状态至少包含最近检查、最近成功、下次检查、数量和最近错误。
- 列表按新到旧展示，并明确标记“定时备份”“恢复前保护备份”“文件损坏”。
- 有效项可以进入现有待恢复摘要区域；损坏项禁用恢复。
- 选择自动备份和选择本地 JSON 文件共用一个 `pendingDocument` 恢复确认状态，新的选择覆盖旧选择。
- 自动备份区失败不得隐藏或禁用现有手动导出和文件导入。
- 继续展示备份可能包含 Provider API Key 的敏感信息警告。

## 错误与边界处理

- 设置文件缺失：按默认开启处理。
- 设置文件损坏：展示设置读取错误，本次不自动写入；用户重新切换开关时覆盖为合法设置。
- 备份目录不存在：首次创建时建立。
- 当前数据未加载：不启动检查。
- 当前版本已有备份：不重复创建。
- 检查任务重叠：跳过后发任务，不排队堆积。
- 自动备份写入失败：保留全部旧文件，主数据保存不受影响。
- 单个文件损坏：保留文件、标记损坏、禁用恢复，其他文件正常使用。
- 保护备份失败：中止恢复，不调用 `replaceDocument()`。
- 恢复目标保存失败：回滚内存文档，保留保护备份。
- 应用关闭：清理前端定时器；不保证关闭时额外创建备份。
- 系统休眠：恢复后按定时器下一次实际触发进行检查，不补跑休眠期间所有间隔。
