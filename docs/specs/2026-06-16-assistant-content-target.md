# 助手草稿回填目标章节

## 背景

助手回复可以回填到正文工作台，但当前插入目标默认是正文页当前选中的章节。用户从助手页回到正文页时，当前选中章节可能不是原始发送章节，存在误插风险。

## 目标

- 正文工作台的 AI 草稿待插入面板允许用户显式选择目标章节。
- 从正文页发起 AI 动作时，助手页回填结果默认建议原始章节作为目标。
- 每条助手回复应使用自己的来源章节，避免同一对话里多次从不同章节发起时串用目标。
- 来源章节需要持久化在 assistant 消息上，刷新或重新打开对话后仍可作为回填建议。
- 追加或替换时写入所选目标章节，而不是隐式依赖当前选中章节。
- 插入完成后自动切换到被写入章节，便于用户继续编辑和校对。

## 非目标

- 不持久化待插入草稿。
- 不自动推断助手回复来自哪个章节。
- 不增加版本对比、撤销栈或差异预览。

## 用户流程

1. 用户在助手页点击“回填正文”。
2. 应用跳转到正文工作台。
3. 待插入面板展示 AI 草稿，并显示目标章节选择器；如果草稿来源于某个章节，默认选中该章节。
4. 用户选择章节后点击“追加到正文”或“替换正文”。
5. 应用写入所选章节，清空草稿，并切换到该章节。

## 技术方案

- 在 `ContentWorkspace.vue` 为待插入草稿新增 `assistantDraftTargetEntryId`。
- 扩展助手 prompt handoff，记录 `sourceContentEntryId`。
- 扩展助手正文草稿 handoff，记录 `suggestedEntryId`。
- 助手聊天发送时把来源章节写入本轮 assistant 消息的 `sourceContentEntryId`。
- 存储 schema 升级到 v11，归一化时保留非空来源章节并清理空白来源。
- 草稿进入正文页时，优先选择 `suggestedEntryId`，否则选择当前章节或第一个章节。
- 插入时根据 `assistantDraftTargetEntryId` 查找目标章节，调用正文合并 helper 后更新目标章节。
- 新增一个纯 helper 更新单个目标 entry，便于单元测试覆盖“只改目标章节”。

## 验收标准

- 待插入面板显示目标章节选择器。
- 从正文页发送到助手再回填时，默认目标章节是原始章节。
- 同一助手对话中多条回复来自不同章节时，每条回复回填到自己的来源章节。
- 旧 v10 文档迁移到 v11 后，assistant 消息的有效来源章节字段被保留。
- 用户选择其他章节后，追加或替换只影响该章节。
- 插入完成后草稿清空，并切换到被写入章节。
- 如果目标章节不存在，插入不会修改正文。
