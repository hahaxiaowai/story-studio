# 大纲情节点关联章节规格

## 背景

当前 Story Studio 已经具备大纲时间轴和正文工作台，但两个模块仍是并列关系。写作者从情节点进入章节写作时，需要手动记住“哪个章节对应哪个情节点”，也无法在正文中看到当前章节承接的大纲目标。

## 目标

- 允许章节关联一个大纲情节点。
- 在正文工作台显示和编辑当前章节关联的情节点。
- 在大纲输入模式中显示情节点是否已有对应章节，并允许从情节点侧绑定章节。
- 保持关联为轻量数据关系，不改变正文和大纲的核心结构。

## 非目标

- 不实现一个情节点拆成多个章节。
- 不实现一个章节覆盖多个情节点。
- 不在本次实现里从情节点自动生成章节正文。
- 不做拖拽排序、复杂跳转历史或导出映射。

## 用户流程

1. 用户进入正文工作台，选择一个章节。
2. 用户在“关联情节点”下拉框中选择当前作品的大纲情节点。
3. 页面显示关联情节点的标题、时间和摘要。
4. 用户进入大纲输入模式，情节点卡片显示是否已关联章节。
5. 用户在情节点编辑器中也可以选择对应章节。
6. 如果某个章节关联到新情节点，旧情节点自动解除；如果某个情节点被新章节占用，旧章节自动解除，保持一对一关系。

## 数据模型

- 在 `WorkspaceContentEntry` 上新增可选字段 `outlineBeatId?: string`。
- 字段只保存同一 workspace 下 `TimelineBeat.id`。
- 旧数据迁移时缺省为 `undefined`。
- 如果存储中已有无效 `outlineBeatId`，迁移时清理。

## UI 结构

- 正文工作台：
  - 在卷/章输入旁新增“关联情节点”选择框。
  - 下方显示当前情节点摘要；未关联时显示提示。
- 大纲输入模式：
  - 情节点列表卡片显示关联章节名。
  - 情节点编辑器新增“关联章节”选择框。

## 验收标准

- 新建章节默认不关联情节点。
- 章节可关联当前作品中的一个情节点。
- 同一个情节点不会被多个章节同时关联。
- 同一个章节不会同时关联多个情节点。
- 旧数据缺少 `outlineBeatId` 时可正常迁移。
- 正文页和大纲输入模式都能显示关联状态。
